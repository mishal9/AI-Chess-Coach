# Experiment: Qwen3-8B QLoRA fine-tune (v1 dataset) vs prompted 3B baseline

**Date:** 2026-08-08 · **Status:** complete · **Verdict: beats baseline (+0.59 overall), quality gates not yet met**

First fine-tuning result of the project. A Qwen3-8B student fine-tuned with QLoRA on 82
teacher-distilled coaching examples outperforms the prompted Qwen2.5-3B baseline on every
judged axis of the 29-game held-out set, and essentially eliminates the motivating failure
mode (inventing mistakes in clean games). Strict grounding regresses slightly due to a new,
milder failure mode: citing illustrative moves outside the provided facts block.

---

## 1 · Hypothesis

A small local coach LLM, prompted with engine-verified facts, still hallucinates
moves/tactics — most severely when the engine flags *no* mistakes for the coached side
(the model invents some). Supervised fine-tuning on `(facts → coaching)` pairs distilled
from a much stronger teacher should teach the small model to stay inside the facts while
coaching more usefully.

## 2 · System under test

```
PGN → engine.analyzer (Stockfish 18, depth 15) → report facts block
    → coach (LLM via Ollama, temperature 0 during eval)
    → eval.grounding (deterministic) + eval.judge (LLM rubric)
```

- **Facts block:** deterministic rendering of the analysis report (`coach.prompts`);
  byte-identical between teacher distillation, student training, and eval.
- **Move-quality classification:** Lichess win-probability model
  (`WIN_PROB_K = 0.00368208`); mistake thresholds 0.10/0.20/0.30 win-prob drop;
  ACPL from capped-eval centipawn loss.

## 3 · Data

### 3.1 Training corpus (public, CC0)

137 Lichess games assembled by `training.corpus`: rating-spanning roster (Maia bots
maia1/5/9 ≈ 1100/1500/1900 Elo, an IM, a super-GM) so mistakes at every level are
represented. Leakage-safe against the held-out set by **both** Lichess GameId **and**
normalized-movetext hash (catches re-exports with stripped tags). Corpus artifacts are
reproducible and gitignored.

### 3.2 v1 distillation dataset (the training signal)

- **Teacher:** `claude-opus-4-8`, system prompt = deployed coach prompt + excellence
  layer; the teacher sees the **student's byte-identical facts/user turn**, so pairs are
  `deployed-prompt → gold`.
- **Grounding gate:** each generation is self-checked with `eval.grounding`; only
  **strict 1.0** (every cited move present in facts) is kept: **104/137 pass (76%)**,
  mean pre-gate grounding 0.945. The 33 rejects each cited a move outside the facts
  block — precisely the habit we are trying not to distill.
- **Splits:** one row per game; leakage-safe per-game SHA-256 split →
  **train 82 / val 9 / test 13** (`training/datasets/v1/`, chat format, committed).

### 3.3 Held-out evaluation set

29 Lichess CC0 games in six mistake-profile buckets (clean_draw 4, slow_loss 5,
inaccuracies 5, two_mistakes 5, one_blunder 5, multi_blunder 5), curated by
`eval.expand_heldout` (Stockfish-classified, disjoint from the corpus by fingerprint).
History note: the original held-out set was 6 games; the first baseline on it
(grounding 0.76 / factual 2.33 / overall 3.04) proved to be a pessimistic small-sample
draw and was **re-baselined** on the 29-game set before any fine-tune comparison.

## 4 · Metrics

1. **Grounding** (`eval.grounding`, deterministic, no LLM): SAN moves cited by the
   coaching are diffed against the exact facts block the model received;
   cited-but-absent = hallucinated. Also: % of games with perfect grounding and a
   worst-move-identified proxy.
2. **Rubric** (`eval.judge`, LLM-as-judge = `claude-opus-4-8`): factual_correctness,
   clarity, actionability, identifies_key_mistake, each 1–5; overall = mean.

**Quality gates for shipping** (agreed 2026-08-08): grounding ≥ 0.85 **and** judge
factual ≥ 4.0 on the held-out set.

## 5 · Training setup

| Component | Value |
|---|---|
| Base model | `Qwen/Qwen3-8B` (hybrid reasoner, used in **non-thinking mode** end-to-end) |
| Method | QLoRA: NF4 4-bit base (double-quant, bf16 compute) + LoRA |
| LoRA | r=16, α=32, dropout=0.05, all 7 linear projections |
| Objective | TRL `SFTTrainer` on chat-format rows (assistant-completion loss) |
| Batch | per-device 2 × grad-accum 8 = effective 16 |
| LR / schedule | 1e-4, cosine, warmup 5% (3B run used 2e-4) |
| Epochs | 3 (≈15 optimizer steps on 82 rows) · seed 0 · max_length 2048 |
| Optimizer | paged_adamw_8bit |
| Hardware | RunPod secure RTX A5000 24GB (US-IL-1), ≈55 min, **≈$0.25** |
| Export | merge fp16 → llama.cpp GGUF f16 → **q4_k_m (4.7GB)** → Ollama |
| Notebook | `training/qlora_8b_runpod.ipynb` (env-adaptive; Colab T4 smoke mode) |

Deployment detail: Qwen3 defaults to thinking mode in some runtimes; `coach.client`
strips a leading `<think>` block so grounding/judging always see plain coaching text
(PR #25).

Comparison caveat: an earlier Qwen2.5-3B QLoRA (v1 dataset, 1 epoch, Colab T4,
`training/qlora_v1_colab.ipynb`) was trained and exported but **not evaluated** — the
8B superseded it before its eval ran. Its GGUF exists locally if a 3B-fine-tune
ablation is ever wanted.

## 6 · Results (29 held-out games, judge = claude-opus-4-8, coach temp 0)

Baseline = prompted `qwen2.5:3b-instruct` (no fine-tune), same facts, same judge.
Reports: `eval/reports/baseline_29g_2026-07-10.json` → `eval/reports/8b_v1_2026-08-08.json`.

| Metric | Baseline | 8B v1 | Δ | Gate |
|---|---|---|---|---|
| Grounding (mean) | 0.81 | 0.79 | −0.02 | ≥ 0.85 ✗ |
| Grounded games % | 55.2% | 41.4% | −13.8pp | — |
| Worst-move identified % | 72.4% | 72.4% | 0 | — |
| Factual correctness | 2.90 | **3.45** | **+0.55** | ≥ 4.0 ✗ |
| Clarity | 3.72 | **4.17** | +0.45 | — |
| Actionability | 2.72 | **3.48** | +0.76 | — |
| Identifies key mistake | 4.17 | **4.76** | +0.59 | — |
| **Overall** | 3.38 | **3.97** | **+0.59** | — |

Paired per-game factual (same games): **14 better · 8 same · 7 worse**.

### Per-bucket deltas (8B − baseline)

| Bucket | n | Δ grounding | Δ factual | Δ overall |
|---|---|---|---|---|
| **clean_draw** | 4 | **+0.50** (0.38→0.88) | **+2.25** | **+1.69** |
| slow_loss | 5 | +0.10 | +0.80 | +0.70 |
| inaccuracies | 5 | −0.24 | −0.40 | +0.05 |
| two_mistakes | 5 | −0.23 | +0.20 | +0.60 |
| one_blunder | 5 | −0.23 | +0.00 | +0.20 |
| multi_blunder | 5 | +0.06 | +0.80 | +0.50 |

### Findings

1. **The motivating failure mode is essentially fixed.** clean_draw — where the
   baseline invented mistakes because the facts block contained none — improved from
   grounding 0.38 / near-worst factual to grounding 0.88 with factual +2.25. This is
   the strongest evidence that distillation transferred the "stay inside the facts"
   behavior where it matters most.
2. **A new, milder failure mode appeared: citation discipline.** The fine-tuned model
   writes richer coaching that cites *more* moves, including illustrative alternatives
   not present in the facts block. The strict grounding metric penalizes every such
   citation, so the previously near-perfect mistake buckets (0.94–0.96) each lost
   ~0.23 grounding while their judged factual scores held or rose. The two metrics
   diverging is informative: judged accuracy up, strict citation compliance down.
3. **Scale + distillation beat prompting on every judged axis** at a total marginal
   training cost of ≈$0.25 GPU + ~137 teacher calls.

## 7 · Threats to validity

- **Judge–teacher circularity:** the rubric judge and the distillation teacher are the
  same model (`claude-opus-4-8`); the judge may prefer its own style. The deterministic
  grounding metric is the check that does not share this bias — and it is the metric
  that regressed, which strengthens rather than weakens the circularity concern for the
  rubric gains. A second judge (e.g. `gemini-2.5-pro`, already pluggable via
  `eval.backends`) should be run before any publication claim.
- **Small n:** 29 games; bucket-level deltas rest on 4–5 games each. Proportion metrics
  move ~3.4pp per game. No significance testing yet.
- **Single seed, single run** for both training and (temp-0) evaluation.
- **Confounded comparison:** baseline is *prompted 3B*, treatment is *fine-tuned 8B* —
  scale and fine-tuning are entangled. The unevaluated 3B fine-tune would separate them.
- **Strict grounding is a conservative proxy:** it counts legitimately illustrative
  moves as hallucinations; a "cited-move verifiable-by-engine" variant would separate
  fabrication from elaboration.
- **Quantization:** eval runs the q4_k_m student, not the merged fp16 weights.

## 8 · Reproduction

```bash
# eval the fine-tuned coach (needs the GGUF registered in Ollama)
ollama create qwen-coach-8b-v1 -f models/Modelfile.qwen-coach-8b-v1
python -m eval.run --coach-model qwen-coach-8b-v1 --judge anthropic \
    --out eval/reports/8b_v1_2026-08-08.json
python -m eval.compare eval/reports/baseline_29g_2026-07-10.json \
    eval/reports/8b_v1_2026-08-08.json
```

Training: `training/qlora_8b_runpod.ipynb` (RunPod A5000 + network volume; Colab T4
runs the same file in smoke mode). Dataset build: `training/README.md`.
Run manifest (persisted with the artifacts): `manifest_8b_v1.json` on the training
volume — LoRA/SFT config, GPU, dates.

## Engineering notes (for the record)

Library drift dominated the debugging cost of the training pipeline; all fixes live in
the notebooks (PRs #20–#25): unpinned bitsandbytes for Triton 3.x, current TRL SFT API
(removed `DataCollatorForCompletionOnlyLM`), Colab's stale preinstalled torchao rejected
by newer peft (uninstall), `extra_special_tokens` list written by new transformers and
unreadable by the older transformers llama.cpp pins (strip before GGUF conversion),
`del model` without `gc.collect()` leaking ~7GB of cyclic-referenced training memory
into the merge (OOM on 24GB), and peft's disk-offload merge being broken outright
(`KeyError` in `_update_offload` — skip merge below 20GB VRAM instead).
